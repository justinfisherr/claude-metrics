# Jazz model audit — 2026-10-21

## Verdict

The model's headline number was not measuring taste. Leave-one-out R² = 0.7588 came
from rating-derived averages that had seen the other tracks on the same album, and
the live scorer fed the model candidates with none of the tags it depends on. Scored
the way the app actually scores them, recommendations had essentially no signal
(Spearman 0.079) and every candidate landed in a 4.3–6.0 band.

This audit removes the leak, makes train-time and scoring-time features identical,
and replaces the headline metric with an unseen-album holdout. The honest model is
much weaker than the old chart claimed: **Spearman 0.25** on records it has never
seen. It is now a real, measured number.

## Evidence (before)

| Check | Result |
|---|---|
| Dashboard headline (LOO R²) | 0.7588 / RMSE 1.04 |
| Shuffle the 17 rating-derived features, same LOO | **R² 0.1052** |
| Album-grouped holdout, same features | **R² −0.0142** |
| Within-album Spearman (can it pick the better track on a record?) | 0.145 |
| `has_elite_collaborator` correlation with rating | 0.426 as coded → **0.153** with the track's own rating removed from the elite set |
| Deployment-style scoring, 80 rated tracks | **Spearman 0.079**, predictions 4.31–6.03 (sd 0.20) |
| Same track in place vs appended as a candidate | My Favorite Things **9.09 → 4.94**; mean shift −1.04 |
| File order vs rating date | corr 0.84 — "recency" features were measuring list position |

Why the album holdout matters: ratings arrive album-by-album, and 54% of tracks are
in multi-track albums. Encodings that exclude only the row itself still contain its
seven siblings. The model was rewarded for remembering which record was playing, not
for predicting a new one.

## Evidence (after)

504 rated tracks (full live DB snapshot), model features 151 (no audio, no
rating-derived means, no missingness flags), deployed model chosen by the holdout
rather than in-sample R².

| Candidate | Unseen-album Spearman | Top-decile lift | Unseen R² |
|---|---|---|---|
| **k-NN (deployed)** | **0.247** | 0.83 | 0.061 |
| Gradient boosting | 0.223 | 0.57 | −0.003 |
| Ridge | 0.200 | 0.68 | −0.462 |

Broken down by where the rating came from, the number that matters for discovery is
much weaker:

| Discovery source | n | Unseen-album Spearman |
|---|---|---|
| claude-recommendation | 249 | 0.356 |
| self | 122 | **0.065** |
| unknown | 101 | 0.108 |

The recommender is good at ranking the tracks it chose (they were selected to fit the
profile) and close to useless at ranking music Justin found himself. That is now
stated on the dashboard instead of being averaged away.

- Candidate posture: in-place vs as-new scores now differ by **0.000** on 15 sampled
  tracks (mean and max). A score no longer depends on where the row sits.
- Tracks with an empty instrumentation list are no longer reported as "pianoless"
  (they were: 221 of 504 rows). Deriving instrumentation from personnel was tested
  and rejected — it lowered unseen-album ranking for all three models (k-NN 0.247 →
  0.231), so missing tags stay missing and the gap is visible in diagnostics.
- Two other model ideas were tested and rejected on the holdout: per-musician identity
  flags (64 flags: k-NN 0.247 → 0.238) and adding the missingness flags to the model.
  They stay out. Feature inventiveness is not the bottleneck; 504 ratings are.
- Scoring with tags produces a real spread again (e.g. Imaginary ballad 5.42 vs
  Imaginary free-jazz blast 3.34 vs untagged 3.76), instead of everything ≈ 5.
- Rating-derived encodings are still computed for the correlation panel but are not
  fed to the model. On the holdout they contributed −0.002 Spearman, i.e. decoration.
- LOO R² is now ~0.00. That is the honest in-sample number and is deliberately not
  the headline.

## What changed

- `train.py`
  - Rating encodings exclude the row **and every track on the same album**.
  - Removed all index/order/recency features (`rating_order_percentile`,
    `recency_weight`, `is_recent`, `ewma_taste_level`, `artist_recent_period_delta`)
    and the percentile-threshold `has_elite_collaborator` / `leader_was_elite_sideman`.
  - Unrated rows are supported: they contribute nothing to any aggregate, which makes
    "append a candidate" and "score it in place" the same computation.
  - `album_holdout()`: album-grouped CV with per-fold feature rebuild, rank metrics
    (Spearman, top-decile lift), and challengers ridge / gradient boosting / k-NN.
  - The persisted model is the holdout winner; `model.joblib` records `model_type`.
  - `TARGET_ENCODING_KEYS` keeps the rating means out of the model in one place.
- `predict.py`
  - No placeholder rating, no position-dependent features.
  - Titles lose packaging suffixes ("- Remastered 2000/Rudy Van Gelder Edition") so
    Spotify search, dedupe, and display agree.
  - `normalize_candidate()` maps LLM tags onto the trained vocabulary and fills
    instrumentation from `key_players` — the deployed scorer previously saw only
    Spotify audio and `era="Unknown"` for every candidate.
  - Model is cached per process (the recommender scores a batch per request).
- `eval.py` — `python3 eval.py [--parity] [--leak]`: the holdout, the score-parity
  check, and the with/without-encodings comparison.
- `tests/test_honesty.py` — 8 tests covering: no order features, no rating means in
  the deployed model, masking self/sibling preserves features, in-place = new
  candidate, tag normalisation, no crash on unrated candidates, scores not collapsed.
- `src/components/panels/Metrics.jsx` and `ModelHistory.jsx` — the dashboard now
  headlines unseen-album Spearman and lift, names the deployed model, and marks the
  pre-v10.14 R² history as album-contaminated.
- `db.py` + `jazz-score-api`
  - `build_candidate()` accepts recommender tags; the prompt now asks the LLM for
    era / primary instrument / subgenres / moods / instrumentation / tempo /
    complexity, so the scorer has inputs. Verified live: `The Joker` came back with
    era Hard Bop, trumpet, five instruments, and scored 5.92 instead of ~5.0.
  - New `recommendations` table logs every pick shown (score, model, source, prompt,
    inferred tags). `reco_report.py` joins it to later ratings and prints precision,
    calibration by score bucket, and tag coverage.
  - Live title cleaning strips remaster/mono/version noise.
  - Synced pipeline + model; deployed to https://jazz-score-api.vercel.app.
- Dashboard: the performance panel also shows the self-discovered Spearman, and the
  cluster panel admits the separation is weak (silhouette ~0.06).

Dashboard: https://claude-metrics-five.vercel.app (v10.20, deployed = k-NN).

## Still open (deliberately not done here)

1. **Remaining data debt.** 231 of 504 tracks have no `energy` tag (silently defaulted
   to 5), 98 no tempo, 122 no complexity, 70 no label, 50 no key players. The
   missing-tag flags are computed and shown in correlations but kept out of the model.
   Filling these with real values, not derived ones, is the remaining win — the derived
   instrumentation experiment made the model worse, so guesswork is not the answer.
2. **Clusters.** k = 2–4 at silhouette ≈ 0.06; the panel now says so, but the segments
   still are not a real taxonomy.
3. **Candidate tags are inferred.** The LLM supplies the metadata the scorer uses. It is
   much better than "Unknown", but a wrong era or personnel changes the score; `tags`
   are logged so this can be audited.
4. **Self-discovered performance.** Spearman 0.065 on music Justin found himself. The
   model is not ready to drive discovery; treat its ordering as a weak hint.
5. **Selection bias in the dataset.** ~50% of ratings are recommender-sourced. Any future
   model comparison should quote the by-source split, not just the aggregate.
6. **One duplicate Spotify ID** and one unrated row in `tracks`; a single write path for
   ratings would prevent both.
7. **Docs.** `SYSTEM_SPEC.md` still carries v6-era detail under an evaluation warning.
8. **Not committed.** Working-tree changes only; the GitHub Action commits artifacts when
   a release is cut.
